# Shared Electron desktop migration

- The existing `windows/` client is the complete Electron desktop implementation and runs as the shared desktop source for both Windows and macOS instead of maintaining two renderer copies.
- The renderer intentionally requires `window.resonance` from Electron's preload script. The old browser fixture bridge and web-rendered UI preview were removed; remote preview distributes a verified source ZIP for a local Electron build instead.
- Preserve the production macOS compatibility bundle identifier `com.gavindietrich.LikedSongsFocus`, the existing `Resonance-macOS.zip`, `Resonance-Installer.pkg`, and `latest-mac.json` release contract, and the `~/Library/Application Support/Resonance` data location.
- Packaged macOS must use the private file credential/session policy rather than Electron `safeStorage`, because Electron `safeStorage` can involve macOS Keychain and the project explicitly forbids Keychain-backed runtime account/server-secret persistence.
- Native Swift stored most library state in bundle-scoped `UserDefaults`; Electron stores `library.json` under `userData`. A safe migration must import native state without deleting the source preferences and must preserve local media paths.
- Removing Swift means replacing `mac/Package.swift`, `mac/Sources`, `mac/Tests`, Swift build scripts, macOS CI cache/toolchain steps, and release-version references with shared Electron commands and tests before deleting the old sources.
- `ffmpeg-static` downloads one architecture-specific executable and skips a rebuild when that file already exists. Universal macOS packaging must rebuild/capture arm64 and x64 binaries, combine them with `lipo`, keep `node_modules/ffmpeg-static/ffmpeg` unpacked, and verify both slices in the final ZIP; the macOS Electron config also carries `install-update.sh` into `Contents/Resources`.
- The macOS PR workflow supplies blank certificate-link variables for unsigned development builds. Unset blank `CSC_LINK` and `CSC_INSTALLER_LINK` before invoking electron-builder; otherwise it resolves the empty value to the `windows/` project directory and fails with `windows not a file`. Preserve non-empty and production signing inputs.
- macOS `UserDefaults` playback queues can arrive as plist arrays rather than encoded JSON. Native transfer-mode defaults are dynamically keyed by a SHA-256 server/profile scope, including the historical production origin, so migration must read both the historical and canonical scopes and persist under the canonical origin.
- The macOS migration suite also runs on Windows CI. Decode drive-less native `file:` URLs with POSIX semantics, accept host-native absolute fixture paths, and resolve all migration roots consistently so the test host cannot reinterpret macOS paths or create drive-relative identity mismatches.
- App-owned support files must be copied and verified before `library.json` and credential/session state are persisted and read back. Delete native sources only after all persistence succeeds; retries must reuse identical `Legacy Recovery` copies and retain source data after partial copy failures.
- Remote preview never renders the app or supplies commands. It serves only the versioned manifest and content-addressed source ZIP; application behavior must be tested through Electron builds and the preload IPC bridge.
- Interactive library, storage, and remote rows expose a real primary `<button>` plus separate secondary controls. Keep the group wrapper non-focusable so screen readers announce a control instead of a generic focusable container.
- Remote-preview protocol v1 exports a 24-hour immutable working-tree snapshot through `/__resonance/preview/v1/manifest.json` and a content-addressed `/__resonance/preview/v1/source/<sha256>.zip`. The target is `macos-electron-preview`; preserve the exact manifest schema, required launcher/package/lock files, same-origin URL rule, no-symlink ZIP policy, and exclusions for Git internals, secrets, dependencies, build output, local app state, and media libraries.
