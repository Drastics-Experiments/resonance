# macOS provider playlist downloads

- YouTube playlist parsing carries a source-row position cursor across continuation pages. Fallback positions advance for every legacy or lockup row, including unavailable and duplicate rows; explicit indices are normalized against the cursor so page-local or backward values cannot reorder tracks. The service carries the parser's last position independently of deduplication and the 500-track output cap.
- YouTube playlist resolution carries a `truncated` state when the 500-item or 10-continuation limit drops candidates or when a continuation remains after a repeated token, unavailable page, or other pagination stop; macOS shows that state beside the selectable items.
- Repeated YouTube rows are valid position-distinct playlist occurrences: parser/service output preserves their source positions, selection keys combine position with track ID, and only the transfer queue de-duplicates a repeated track ID.
- Playlist imports must snapshot the selected media mode before the async batch: propagate it to the transfer context, existing-song matching, and every candidate import so Video produces video tracks and does not reuse audio-only local or server matches. Regression fixtures cover the pre-fix `.video` -> `.audio` behavior and the fixed end-to-end path.
- Do not reject a YouTube playlist merely because its initial page has no playable rows when it still has a continuation. Let the bounded service pagination finish, then apply the final empty-playlist check; a regression covers an unavailable first row followed by a playable continuation row.
